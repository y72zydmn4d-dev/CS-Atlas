# Tutorial taxonomy

## Catalog-level families observed

- Web foundations and frameworks
- Programming languages
- Databases and query languages
- Data science and statistics
- AI and machine learning
- Cyber security
- Developer tools and platform-specific tutorials
- References/utilities that are not full curricula

## Subject taxonomy patterns

- **Languages:** setup → syntax/types/operators → control flow/functions → collections → OOP/modules/files/errors → advanced/runtime/library reference.
- **Web:** document/styling/language core → browser APIs → responsive/accessibility → frameworks/projects/references.
- **Database:** query syntax → filtering/joins/aggregation → schema/constraints → administration/security → functions/reference.
- **Data libraries:** setup → core data structure → selection/transformation → IO/cleaning → analysis/visualization.
- **DSA:** structures and algorithms with complexity commentary; current public coverage is much shallower than the Atlas target.
- **AI/ML:** uneven; some material is nested under Python and lacks a complete independent activity/reference system.

## Atlas opportunity

Atlas should treat catalog category, subject, curriculum section, lesson, Concept and reference category as distinct typed layers. A label visible in a catalog is not automatically a canonical Concept or an independent subject root. Status (`PLANNED`, `SKELETON`, `PARTIAL`, `COMPLETE`) must be explicit so breadth does not masquerade as depth.
