# Lesson anatomy

## Observed recurring sequence

1. Subject/curriculum context and page title.
2. Previous/Home/Next controls near the top.
3. Short explanatory sections.
4. Examples embedded close to the concept they demonstrate.
5. Try/editor action where a runtime exists.
6. Notes, warnings, tables or visual explanations.
7. Lesson-local exercise or challenge.
8. Related/reference links and repeated previous/next navigation.

This pacing keeps explanations scannable and makes action available before the learner loses context. It also scales because each lesson is a sequence of reusable block types rather than an entirely bespoke page.

## Atlas block implications

Atlas needs independently authored typed blocks for paragraphs, headings, lists, definitions, syntax, code, worked/runnable examples, output, callouts, tables, formulas, comparisons, visualizations, mistakes, best practices, exercises, quizzes, references and related content. Blocks must remain optional, carry stable IDs, and connect to lesson/Concept identity without duplicating canonical metadata.

The renderer should keep text width comfortable even when the workspace uses a wide monitor. Code and tables may use the center-column width or controlled breakout behavior; prose should not simply stretch to fill available space.
