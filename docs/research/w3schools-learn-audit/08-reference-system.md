# Reference system study

## Observed separation

References are more compact and scan-oriented than tutorials. Mature subjects expose category indexes, dense tables and individual entries. HTML/CSS/JavaScript/SQL/PHP/Java have broad reference systems; NumPy/Pandas are narrower; DSA uses “Reference” as an advanced-topic grouping rather than a conventional API index.

Common reference fields include a name/symbol, signature or category, short description, availability/support notes and a detail link. Tables and alphabetical/category groupings dominate; marketing cards do not.

## Atlas design

- `ReferenceRecord` is distinct from `LessonManifest`.
- Categories support compact accessible tables, search and alphabetical grouping.
- Records carry stable ID, subject, category, signature/name, concise original description, related lesson IDs and canonical Concept IDs.
- Detail pages are optional: simple entries can remain rows, complex semantics can receive a route.
- Reference status and provenance are validated independently from tutorial completeness.
- Tables use semantic headers, captions or labelled regions, keyboard-reachable links and responsive overflow.
