# Final findings

## What makes the learning system scalable?

Stable page archetypes, subject-scoped ordered sidebars, compact content sections, reusable example/exercise patterns and separate dense references allow very large curricula to remain predictable. Subject pages can vary in depth while sharing the same navigation grammar.

## What makes tutorial navigation efficient?

The curriculum is always near the lesson, grouped into named chapters, active-state aware and reinforced by previous/next controls. The user can either scan the full course or move linearly without returning to a catalog.

## Which page archetypes exist?

Catalog, subject home, lesson/sub-lesson, exercise hub/item, examples index, quiz, reference index/table/item, syllabus, study plan, editor/Try-It and special interactive pages.

## How are tutorial, exercise and reference separated?

Tutorials teach in authored sequence. Exercises are chapter-aligned retrieval tasks with progress state. References are compact lookup surfaces organized by category/symbol and may link to detail entries. They cross-link, but they do not share the same content contract.

## Behaviors Atlas should adopt

- Persistent subject curriculum with grouped lessons and active/completed state.
- Strong previous/next navigation.
- Examples beside the explanation they serve.
- A stable edit/run/output/reset pattern where runtime capability is real.
- Chapter-derived exercise hubs and subject/section quizzes.
- Dense searchable reference tables.
- Explicit responsive transformation from columns to drawers/popovers.
- Honest content and runtime availability.

## W3Schools-specific behaviors Atlas should not adopt

- Historical `.asp`/`.php`, casing and query-parameter route inconsistency.
- Branding, typography, green palette, proprietary copy, examples, exercises or components.
- Treating every catalog label as a separate canonical knowledge root.
- Mixing tutorial navigation with sales/certification prompts.
- Template gaps or activity availability that is not explicitly modeled.
- Shallow AI/ML/DSA coverage or labeling advanced tutorial topics as API reference.

## What Atlas can do better for DSA, AI and CS

Atlas can connect every lesson to canonical Concepts, prerequisites, Roadmaps, Mind Maps, Problems, resources and evidence. DSA can extend through proof ideas, patterns, advanced graphs/DP/range/string/number-theory/geometry topics and reusable visualizations. AI can connect mathematics, model evaluation, implementation and responsible system design rather than remain a collection of isolated examples.

## Current Atlas structures that must change

The flat `/learn` list, domain-only course projection, one-segment lesson routing, absence of subject/reference/example/quiz manifests, and current two-column lesson shell all need additive evolution.

## Structures that should be preserved

Canonical Concept IDs, authored `content/`, typed blocks/provenance, existing deep topics and URLs, Server Components, browser persistence adapters, Exercise/Problem separation, QuickJS Worker boundary, learning events, unified search, Roadmap/Mind Map distinction, theme/localization and accessibility patterns.

## Research conclusion

The implementation should be an Atlas-native knowledge and tutorial system: a subject catalog, typed curricula, high-density workspace, original lessons, canonical practice/reference integration and explicit maturity. Architecture can be complete while content remains partial; those states must be reported separately.
